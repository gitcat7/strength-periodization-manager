# 核心训练完整性与单日处方编辑设计

## 背景与审计结论

当前生产分支 `codex/checkpoint-pre-p0` 同时包含新排程、邮箱 OTP 和近期页面修复，但它不是此前 `codex/p0-remediation` 的后继。两条分支从共同祖先后分别演进，后续直接从 checkpoint 分支部署，导致此前已经验收的训练时长、原子完成、历史读改分离、严格画像处方和五批移动端体验代码不再位于生产提交中。

这不是单个页面缺陷，而是发布基线分叉。任何新功能都必须先完成分支对账，否则会继续在不完整基线上开发。

当前科学性审计同时确认：现有生成器主要是“固定模板 + 工作组重量比例 + 四周固定波动”。目标、训练经验、伤病、单次时长和恢复倍率多数仅保存或展示，没有进入最终处方；Coach 主要依据完成比例和末组 RPE，并会把同一动作的所有未来 A/B 训练统一改为同一重量。

## 目标

1. 建立唯一、可追溯的生产发布基线，同时保留两条分支中已经验收的能力。
2. 让目标、经验、训练频率、单次时长、动作限制和有效能力基线真实参与计划生成。
3. 让 Coach 和进展分析以实际完成重量、次数、RPE、计划达成率和时间窗口为依据。
4. 允许用户编辑某个未完成训练日的动作结构，并保证完成后的数据自然进入历史、进展、e1RM 与 Coach。
5. 核心重量与处方算法必须确定、可测试、可解释；不依赖大模型产生训练数值。

## 非目标

- 不让大模型直接决定训练重量、组数或伤病后的训练许可。
- 不允许修改已完成或已跳过训练日的动作结构。
- 第一版单日编辑不支持任意外部或手工动作，只允许审核过的本地 `cfg_exercises`。
- 不在本批引入社交、饮食诊断或医疗建议。

## 方案选择

采用“合并对账”而不是逐个挑提交或重写历史：以当前生产提交为骨架，将 `origin/codex/p0-remediation` 合并进新的集成分支，通过行为契约逐项解决冲突。禁止 force push；每个批次必须有独立固定提交、测试窗口结论和生产验收记录。

## 批次 A：生产基线对账

必须同时保留：

- checkpoint 分支：邮箱 8 位 OTP、新排程与暂停/恢复、未来训练不提前、已有计划默认折叠、完成弹窗关闭、桌面小数重量显示。
- p0-remediation 分支：严格画像处方、训练时长追踪、原子训练完成与建议、历史读改分离、计划/今日/首页/进展/设置五批体验优化及其 SQL 契约。

验收不以“能构建”为充分条件。必须建立功能矩阵，对每项能力给出测试文件、迁移文件、生产页面和数据库契约四类证据。当前生产数据库已经由 SQL Editor 执行过部分迁移，因此迁移文件恢复到仓库时必须保持幂等，且不得要求用户重复执行已生效的旧迁移；只对新迁移设置人工门禁。

## 批次 B：科学处方与分析

### 能力基线

- 主项基线只接受 1–10 次、RPE 7–10 的近期稳定工作组；高次数组不直接用于处方 e1RM。
- 使用实际重量、次数与 RPE/RIR 形成候选 e1RM。数据不足时允许新手不填主项，使用“首课建立基线”模式，而不是生成 2–3 kg 的伪精确重量。
- 已有至少半年训练经验时，至少一个主项基线必填；其余主项允许缺失，但必须以首课校准处理。
- `training_max` 必须进入生成器，不再成为只保存不使用的字段。

### 目标与经验规则

- 力量：主项以 3–6 次为主，保持技术余量，辅助量保守。
- 增肌：按肌群分配周有效组数，复合动作以中等次数为主，辅助动作采用次数区间和 RPE 递进。
- 力量与增肌兼备：主项保留低至中次数，辅助动作承担大部分增肌容量。
- 减脂与塑形：不承诺抗阻训练本身造成减脂；保留主项强度，按恢复与体重趋势适度下调总量，并允许 Zone 2 安排。
- 力量举：只有用户明确选择该目标时才提高深蹲、卧推、硬拉专项比例；它不是所有计划的最高优先级。
- 初学者优先 2–3 次/周、更少动作和较低周组数；训练经验增加时才允许更高频率与更复杂的 A/B 变化。
- 训练频率变化时必须保持周总量预算，不能简单复制整套单日模板。
- 单次时长转化为组数与动作数预算，预留热身和组间休息，不生成明显无法在所选时长内完成的计划。

### 动作限制与恢复

- 自由文本伤病备注只用于展示和提醒；处方过滤依赖结构化的禁用动作/受限动作模式。
- 结构化限制命中时，生成器必须删除冲突动作并选择同方向、同目的的审核替代动作；没有安全替代时要求用户调整，而不是猜测。
- 暂停后恢复倍率必须生成明确预览并实际作用于 1–2 次训练；`suppressIncreases` 必须阻止同窗口内 Coach 加重。

### Coach 与 A/B 周期

- Coach 以实际完成重量和次数为基线，要求达到目标次数区间，并综合所有有效组的 RPE，而不是只看末组。
- 实际重量明显低于计划、实际次数未达标或异常组较多时不得加重。
- 接受建议时更新动作能力基线或训练最大值，再按训练日的 A/B 类型、目标次数和强度系数重算未来处方；禁止把所有未来训练统一成同一重量。
- 辅助器械首轮允许用户按次数区间和目标 RPE 自选重量，禁止从深蹲/卧推公斤数跨器械硬推。

### 进展分析

- 查询最近 60 次完成训练：数据库降序取 60，再在客户端升序展示。
- 训练总量仅作为同动作或相近结构下的粗略工作量；页面不得把跨器械吨位解释为训练刺激。
- 计划依从率必须把应训练日纳入分母；停训周不能从趋势中消失。
- e1RM 只使用本地主项、1–10 次有效完成组，并展示日期、来源和估算性质。
- 历史修订后，未处理的 Coach 建议必须重新计算或标记过期；已应用建议不自动回滚，但记录修订事件。

## 批次 C：单训练日处方编辑

### 允许范围

只允许当前用户、当前活动计划、`day_type='training'`、状态为 `scheduled` 或 `draft`，且不存在任何已完成组的训练日。已完成、已跳过、归档计划或已有完成组的训练日禁止结构编辑。

支持替换、删除、新增、调序，以及修改目标组数、次数和重量。第一版动作来源仅为本地审核目录；同一训练日不得重复动作。推/拉/蹲训练日新增动作必须符合该日方向；主项替换需要更严格的审核替代规则。

### 数据模型

- `plan_workouts.prescription_revision integer not null default 1`：训练日级乐观锁，不复用计划级 `schedule_revision`。
- `plan_workout_exercises`：保存最终处方结构。
- `log_set_logs`：保存实际执行事实。
- `ops_workout_revision_events`：保存修订前后摘要和 revision，用于审计，不参与主查询。

### 原子 RPC

新增 `revise_workout_prescription(workout_id, expected_revision, exercises jsonb)`。RPC 必须：

1. 从 `auth.uid()`获取用户并锁定 workout。
2. 验证归属、活动计划、训练日、允许状态和 revision。
3. 锁定现有动作与组记录；存在已完成组即拒绝。
4. 验证动作数 1–12、连续顺序、无重复、本地动作、方向规则、组数 1–20、次数 1–1000、重量 0–10000 kg。
5. 保留未替换动作 UUID 和未完成草稿；替换或删除动作清理对应未完成日志。
6. 原子更新结构、revision 和审计事件；任一步失败全部回滚。

RPC 使用 `SECURITY DEFINER SET search_path=public`，拒绝 `PUBLIC` 和 `anon`，仅授权 `authenticated`。数据库触发器必须阻止通过直接 DML 绕过已完成训练保护。

### 前端与缓存

计划页的每个未完成训练日提供“编辑本次训练”。编辑器显示动作目录、顺序、目标组次和重量，并在保存前显示变更摘要。保存成功后清除 plan/today/history/progress 缓存和该 workout 的草稿，再重新读取训练日。

Today 继续读取 `plan_workout_exercises`，因此编辑后的动作会直接进入执行。完成后，History 与 Progress 从同一三表读取实际完成记录；只有本地主项且有效次数范围内的新增动作进入 e1RM，其他动作进入训练量和完成质量分析。

## 跨批次 P1 安全修复

- 所有训练缓存携带并校验 `userId`；退出登录清除训练缓存和草稿，防止同设备切换账号短暂显示旧数据。
- 暂停/恢复日关键查询失败时 fail-closed；只有明确的旧 schema 兼容错误才允许降级。
- 计划设置画像与主项能力必须通过事务 RPC 一次保存，避免部分成功。
- `release:check` 必须执行 Vitest；数据库门禁必须明确是否执行全部 pgTAP，不能把未运行写成通过。

## 大模型边界

核心计划、重量、组数、动作冲突、恢复倍率、Coach 建议和趋势计算全部采用确定性规则。大模型不是必需依赖。

未来可选使用大模型做三件事：把规则结果解释成自然语言、归纳训练备注、提出需要用户确认的问题。大模型输出不得直接写入计划或覆盖重量；任何建议都必须经过结构化规则校验并由用户确认。

## 验收标准

- 两条分支的行为矩阵全部通过，仓库迁移与生产能力一致。
- 五个主要目标、三档经验、不同频率和时长在相同能力基线下产生可解释的不同处方。
- Coach 使用实际数据，且接受建议后 A/B 重量差异仍保留。
- 未来、暂停、恢复和逾期训练边界不回归。
- 单日结构编辑在数据库中原子完成，跨用户、已完成训练、过期 revision 和非法动作全部拒绝。
- 编辑后的训练完成后正确进入 History、Progress、e1RM 与 Coach。
- 全量 Vitest、typecheck、build、14 路由 smoke 和全部相关 pgTAP 通过后才允许部署。
