# 计划页体验优化需求任务

## 目标

让已有训练计划的用户优先管理当前周期，而非重复创建计划；通过“周 → 训练结构循环 → 训练日”的层级缩短计划页；确保小数重量完整可读、可录入。

## 任务顺序

| 编号 | 优先级 | 任务 | 依赖 | 完成定义 |
| --- | --- | --- | --- | --- |
| PLAN-01 | P0 | 已有计划的管理入口 | 无 | 有计划用户不再看到创建计划主入口 |
| PLAN-02 | P1 | 周与训练结构循环的分层浏览 | PLAN-01 | 长周期计划可按周、循环逐层展开 |
| PLAN-03 | P0 | 小数重量输入显示修复 | 无 | 例如 `22.5` 在手机端完整显示且可编辑 |

---

## PLAN-01：已有计划的管理入口

### 用户故事

作为已有有效训练计划的用户，我进入“计划”菜单时希望立即看到当前周期和管理入口，而不是再次被要求创建计划。

### 交互规则

- 没有有效计划时，保留“创建第一个计划”和“生成 N 周训练计划”入口。
- 有有效计划时，顶部只显示当前周期摘要：计划名称、起止日期、当前第几周、下一个训练日。
- 有效计划状态下不显示“创建第一个计划”或“生成 N 周训练计划”作为主操作。
- 提供两个明确入口：
  - **调整计划**：打开当前计划参数；只有在用户确认“预览并重新生成计划”后才替换后续安排。
  - **重置计划**：打开二次确认对话框，说明会废弃当前周期未完成的后续训练安排，并以当前参数重新生成一套周期；已完成记录和历史数据不删除。
- 现有“体重、饮食与恢复”独立更新入口保留，不触发重置或重建。

### 验收标准

1. 已有有效计划的页面首屏不存在创建计划主卡片或“生成 N 周训练计划”主按钮。
2. 页面首屏显示当前周期摘要与“调整计划”“重置计划”。
3. 调整计划不经确认不得改变现有日程。
4. 重置计划必须经二次确认；确认后仅替换未完成后续安排，历史完成记录可在历史页查看。
5. 无计划用户仍可完整创建 1–12 周计划。

## PLAN-02：周与训练结构循环的分层浏览

### 用户故事

作为使用多周计划的用户，我希望按周查看计划，并在每周内按训练结构循环查看训练日，而不是浏览一整页很长的日程卡片。

### 层级与定义

```
全部计划
└── 第 N 周
    └── 训练结构循环
        └── 训练日 / 休息日
```

- **周**：从计划开始日连续划分的第 1–12 周，不以自然周一至周日为边界。
- **训练结构循环**：由模板的训练方向与 A/B 结构构成的一轮，例如“推 A → 拉 B → 蹲 A”。它不是自然周，也不是单个训练日。
- **训练日/休息日**：循环内最小的可查看项，显示日期、方向、状态及动作处方。

### 交互规则

- 首次进入时仅展开当前周；没有当前周时展开最近一个含未完成训练的周。
- 周标题显示：第几周、日期范围、完成训练数/总训练日数。
- 展开某一周后，显示该周的训练结构循环；每个循环默认收起。
- 循环标题显示结构名称、覆盖日期、完成状态；展开后显示其中训练日与休息日。
- 提供“全部展开”与“全部收起”：
  - 全部展开：展开全部周、全部循环和训练日动作处方。
  - 全部收起：仅保留周标题。
- 同一时刻允许多个周或循环展开；用户切换不会修改数据库计划或训练状态。

### 验收标准

1. 12 周计划首屏不渲染完整训练日清单。
2. 用户可从周展开到训练结构循环，再展开至训练日处方。
3. 每个循环的训练日顺序与原计划 `schedule_index` 一致。
4. “全部展开”“全部收起”行为在移动端可操作，且不改变计划数据。
5. 计划中休息日仍可在所属循环内显示。

## PLAN-03：小数重量输入显示修复

### 用户故事

作为录入主项工作组的用户，我需要完整看见并编辑 `22.5`、`102.5` 等小数重量，而不会被输入框截断。

### 交互规则

- 重量输入字段采用适合小数的数值宽度和右侧对齐，手机窄屏下不得遮挡小数部分。
- 保持 kg 单位、0.5 步进与现有数值校验逻辑。
- 输入、失焦、页面重新渲染后均保留原始小数值，不可将 `22.5` 自动变为 `22`。
- 四个主项工作组输入在最小支持宽度下仍能完整显示至少 `102.5`。

### 验收标准

1. 手机 320px 宽度下，主项重量输入可完整显示 `22.5` 与 `102.5`。
2. 提交后的计划处方使用正确的小数重量；不会发生截断或整数化。
3. 现有重量单位、步进与有效性校验不回归。

## 实施与验证顺序

1. 先实现 PLAN-03，风险低且直接修复数据录入可读性。
2. 实现 PLAN-01，确定已有计划的页面主入口和重置边界。
3. 在 PLAN-01 的计划摘要基础上实现 PLAN-02，避免重构两次日程区域。
4. 每项均需补充针对无计划、有计划、12 周计划、休息日和小数重量的自动化测试；发布前执行 `pnpm release:check` 与线上冒烟检查。
