# 目标驱动计划生成一期设计

## 目标

让创建计划时的训练目标真正决定训练内容。第一期支持两条互斥路线：`力量举风格力量提升` 与 `增肌`。前者服务新手到初级的力量提升，不提供备赛峰值、开把、极限测试或医疗建议。

## 范围

### 纳入

- 创建计划时选择训练路线；旧的泛化“力量”迁移为“力量举风格力量提升”。
- 根据路线、训练天数、周期和主项工作组生成动作、组次、负荷及减量周。
- 力量举路线要求深蹲、卧推、硬拉均有有效最近工作组数据。
- 在计划预览中解释主项频率、强度/容量安排、减量周与负荷来源。
- 将路线和生成规则版本保存到计划，保证历史计划可读、可追溯。

### 不纳入

- 备赛峰值、比赛日反应、开把选择、称重或极限单次测试。
- 自动根据训练完成情况改写整期计划；这继续由训练建议闭环后续阶段处理。
- 新训练目标、饮食、有氧处方或动作视频教学。

## 用户与成功标准

目标用户是有基础动作能力、希望提升三项表现的新手到初级训练者，以及以增肌为主要目标的普通训练者。

当用户选择力量举路线并完成基础数据录入时，生成结果必须满足：

- 只围绕深蹲、卧推、硬拉、各自主项变式和必要的恢复性辅助动作。
- 没有独立手臂日、孤立肩日或与三项无关的高优先级复合主项。
- 每个训练日只有一个主项；其他动作必须服务当天主项的技术、肌群或后链恢复需求。
- 4 周计划中第 1 至 3 周渐进，第 4 周减量。
- 负荷来自用户工作组推导出的现有训练最大值，并按动作默认最小加重取整。

## 路线与输入

### 力量举风格力量提升

必填输入：训练经验、计划周数、每周训练天数、排期、深蹲/卧推/硬拉最近可稳定完成的工作组（重量和次数）。

有效工作组定义：重量大于 0 kg、次数为 1 至 30 的整数。任一三项缺失时，不生成力量举计划；界面应定位到缺失项并提示“力量举路线需要补齐深蹲、卧推和硬拉的最近工作组”。

训练最大值由既有工作组估算逻辑计算；计划重量始终按该动作 `default_increment` 取整，不能高于对应周次的规则上限。

### 增肌

沿用现有增肌输入、计划模板和动作目录。增肌生成不得因本期改动而要求补齐三项工作组；用户可使用既有推拉蹲、一分化、三分化和五分化模板。

## 力量举生成规则

### 周频率

| 每周训练天数 | 深蹲 | 卧推 | 硬拉 | 说明 |
| --- | ---: | ---: | ---: | --- |
| 3 天 | 2 | 2 | 1 | 最小有效频率，三项以一个主项日和一个技术/容量暴露交替。 |
| 4 天 | 2 | 3 | 1 | 增加一次卧推技术/容量日。 |
| 5-6 天 | 2 | 3 | 2 | 第二次硬拉为轻量技术或变式，不作为第二个重主项。 |

一期不接受 1、2 或 7 天作为力量举路线的有效训练频率。界面在选择该路线时限制可选训练天数为 3 至 6 天。

### 训练日结构

- 每日第一个动作是当天唯一主项，标记为“强度”或“容量/技术”。
- 强度主项：3-5 组 x 3-6 次；目标负荷为训练最大值的 72.5%-85%。
- 容量/技术主项：3-4 组 x 5-8 次；目标负荷为训练最大值的 62.5%-75%。
- 次主项或变式：2-4 组 x 5-8 次，服务当日三项模式，例如暂停卧推、节奏深蹲、罗马尼亚硬拉。
- 辅助动作：2-3 个，每个 2-3 组 x 8-15 次，只能为胸背、股四头、腘绳肌、臀部、上背、核心或肩袖恢复服务。
- 不安排孤立手臂作为训练日核心；手臂动作最多作为卧推日最后一个可选辅助动作。

### 三项日序列

生成器使用确定性循环，不随机抽取动作。三天基础循环为：

1. 深蹲强度 + 卧推容量 + 下肢/核心辅助。
2. 卧推强度 + 上背训练 + 推举或三头辅助。
3. 硬拉强度 + 深蹲技术 + 后链辅助。

四天以上在上述循环中加入卧推技术日；五至六天再加入硬拉轻量变式日。每一日标题必须直接显示主项和意图，例如“深蹲 A · 强度”或“卧推 B · 容量/技术”。

### 四周负荷波次

| 周次 | 强度日系数 | 容量/技术日系数 | 目的 |
| --- | ---: | ---: | --- |
| 第 1 周 | 基准 | 基准 | 熟悉负荷和动作质量。 |
| 第 2 周 | +2.5 个百分点 | +2.5 个百分点 | 小幅渐进。 |
| 第 3 周 | +5 个百分点 | +2.5 个百分点 | 本周期最高常规训练刺激。 |
| 第 4 周 | -7.5 个百分点，且组数减少约 40% | -7.5 个百分点，且组数减少约 40% | 减量与恢复。 |

任何动作的计划重量均不得小于 0 kg。体重动作或没有负荷基础的辅助动作保持既有 0 kg 表达，不从三项训练最大值推算。

## 数据模型与兼容性

`programs` 新增：

- `training_goal`：`powerlifting` 或 `hypertrophy`；旧计划按原 `template_type` 映射为 `hypertrophy`，不重写其动作。
- `generation_rule_version`：一期写入 `goal-driven-v1`；旧计划可为空。

创建和替换计划的 RPC payload 必须显式携带这两个字段。数据库应校验路线取值，RLS 继续按现有 `programs.user_id` 生效。已有计划和历史训练不能因迁移失败或缺少新字段而无法读取。

## 界面与反馈

创建计划页的目标控件显示：`力量举风格力量提升`、`增肌`。选择力量举后：

- 可见训练天数仅为 3-6 天。
- 三项最近工作组区域固定展示深蹲、卧推、硬拉并标出必填。
- 预览展示三项周频率、首周训练日列表、第四周减量提示和“训练重量基于最近工作组估算”。
- 缺少数据时，生成按钮禁用并显示明确原因；不产生半成品计划。

选择增肌后保留当前模板选择和现有文案，且不展示力量举专属约束。

## 错误处理

- 路线与训练天数不兼容：阻止预览和保存，提示有效范围。
- 三项数据不足：阻止预览和保存，逐项显示缺失字段。
- 当前动作库缺少所需动作：生成器返回可读错误，不写入数据库。
- 计划替换 RPC 出错：保留预览与用户填写内容，显示数据库错误；不得清空现有有效计划。

## 测试与验收

领域测试至少覆盖：

- 3、4、5、6 天力量举路线的三项频率。
- 每日唯一主项、动作边界、强度/容量组次范围。
- 四周负荷与第四周减量组数。
- 缺少任意三项数据时拒绝生成。
- 增肌路线保持现有模板和不要求三项数据。
- 默认加重取整和无负荷辅助动作。

组件测试至少覆盖：路线切换、字段显隐、禁用状态、预览解释和替换计划 payload。

数据库测试至少覆盖：新列默认值/约束、旧计划读取、路线持久化和用户隔离。

发布验收使用两个真实场景：

1. 选择力量举、每周 4 天并填写三项工作组，生成计划后验证卧推 3 次、深蹲 2 次、硬拉 1 次，且第四周减量。
2. 选择增肌、每周 3 天且不填写三项工作组，生成现有三分化或推拉蹲计划成功。
