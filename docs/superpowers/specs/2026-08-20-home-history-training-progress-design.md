# 首页与历史训练进度展示设计

## 目标

让用户在首页看见当前计划训练的真实逐动作完成进度；让历史页只显示所选日期的训练详情，避免将其它日期记录混入当前选择。

## 范围

- 首页“下一次训练”卡片加载当前待执行训练的组记录，并在每个动作行显示 `已完成 X/Y 组`；卡片顶部显示本次训练总进度。
- 历史页维持月历优先：未选择日期时不显示训练详情；选择某日后，仅显示该日的计划摘要和该日已完成训练详情。
- 从 `claude/history-date-selection` 选择性移植月历相关实现到当前生产基线 `aaed7202114931af2a4bd4124f3e7a7ef145874e`，不整体合并旧分支。

## 非目标

- 不新增或修改 Supabase migration、RLS、RPC、缓存键、计划处方、训练完成、Coach、Progress 或训练算法。
- 不改变动作实际数据、完成状态和历史编辑行为。
- 不在首页提供直接修改组记录的能力；首页只展示并跳转到 `/today` 继续训练。

## 设计

### 首页

首页保留当前活动计划中第一条 `scheduled` 或 `draft` 训练日的选择规则。读取到该训练日动作后，再以这些动作 ID 查询现有 `log_set_logs`；只使用 `completed=true` 的记录计算进度。每个动作显示原始处方和独立的完成状态：未完成显示 `0/3 组`，部分完成显示 `1/3 组已完成`，全部完成显示绿色 `3/3 组已完成`。顶部显示本次合计 `X/Y 组已完成`。查询失败时不伪造完成状态，按安全的 `0/Y 组` 展示并保留继续训练入口。

### 历史

月历的日期摘要继续由当前月训练日构建。日期未选中时，只显示月历和汇总指标；日期被选中时，详情区域只使用该日 `CalendarDay.workouts` 中的 ID。该日的 scheduled/draft/skipped/rest 项保留在摘要中；只有该日 status=`completed` 的训练项进入可查看/编辑的详细记录。切换月份清空选中日期，URL `?workout=` 仅在对应训练属于当前用户且位于当前月时聚焦。

### 数据一致性

首页与历史均以当前用户范围内的数据库结果为准。首页缓存可以先显示上次内容，但不恢复未经当前 active program 校验的下一次训练；刷新后写入现有缓存键。历史月查询继续以 `[monthStart, nextMonthStart)` 限定，避免跨月泄露或混入。

## 验收标准

1. 当前训练深蹲已有 3 个完成组时，首页深蹲行显示 `3/3 组已完成`，总进度同步增加；未完成动作不被标为完成。
2. 首页查询组记录失败时不展示虚假的完成数量，也不影响 `/today` 入口。
3. 历史页未选择日期时不渲染任意训练详情。
4. 选择 2026-07-31 后，不出现 2026-07-18 的详情；所选日期的已完成记录仍能查看/编辑。
5. 切换月份后清空详情；历史 focus URL 保持用户范围和月份边界。
6. 现有 Today、History 编辑、训练量、RPE 与日历测试不回归。

## 验证与发布

按 TDD 分别为首页进度与历史日期过滤添加失败测试并记录 RED→GREEN；运行 focused tests、`pnpm test`、`pnpm release:check`。固定提交推送后先请求测试窗口独立验收；只有测试窗口明确“验证通过”后部署固定提交，再运行正式域名 14 路由与 `/api/health` 冒烟并通知架构验收窗口。
