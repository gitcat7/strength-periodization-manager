# 数据库命名、注释与时间语义治理设计

## 目标

将 `public` schema 中按业务含义混杂的表，重组为带稳定领域前缀的物理表；为全部表与字段补充中文 PostgreSQL 注释；明确日期与时间字段语义；并在不丢失现有训练历史、不降低 RLS 隔离强度的前提下平滑迁移应用。

## 命名边界

| 前缀 | 领域 | 表 |
| --- | --- | --- |
| `cfg_` | 共享配置与动作目录 | `cfg_exercises` |
| `usr_` | 用户画像和能力基线 | `usr_athlete_profiles`、`usr_lift_profiles` |
| `plan_` | 训练计划及其结构 | `plan_programs`、`plan_workouts`、`plan_workout_exercises` |
| `log_` | 用户训练事实和训练建议 | `log_set_logs`、`log_recommendations`、`log_pr_goals` |
| `ops_` | 运营反馈、观测与访问令牌 | `ops_feedback_reports`、`ops_analytics_events`、`ops_agent_access_tokens` |

表名使用复数 snake_case；字段维持既有 snake_case，以避免无价值的字段级破坏性重命名。所有新增的约束、索引、触发器、策略和函数采用相同领域前缀。

## 迁移与兼容策略

1. 迁移以 `ALTER TABLE ... RENAME TO` 完成物理表原地重命名：这会保留 UUID、历史数据、外键、索引、RLS、触发器和依赖对象，不复制数据，也不会产生双写漂移。
2. 先更新全部应用查询和 RPC，使读写直接访问前缀表；SQL 函数体中的引用也同步更新。
3. 在原表名上创建兼容视图，仅服务仍使用旧名称的读取方。兼容视图不赋予写入路径，避免无法审计或绕过 RLS 的兼容写入。
4. 同一迁移内重建所有受改名影响的 RLS 策略与 RPC 函数，并对新物理表启用 RLS。迁移可在有数据的托管项目上执行，且使用条件判断避免重复执行失败。
5. `supabase/schema.sql` 作为新环境的最终基线，直接定义前缀表、约束、策略、函数和注释；迁移文件负责已部署项目升级。

## 时间与日期语义

- 记录创建、更新、完成、失效、撤销和最近使用等“事件时刻”使用 `timestamptz`，由 PostgreSQL 存储带时区的完整年月日时分秒。前端序列化使用 ISO 8601（如 `2026-07-25T11:30:00+08:00`），展示层按用户时区格式化为 `YYYY-MM-DD HH:mm:ss`。
- `start_date`、`end_date`、`scheduled_date`、`target_date` 代表全天或日历日期，保留 `date`，不伪造时分秒或时区。字段注释显式说明这一差异。
- `updated_at` 由统一触发器维护，避免客户端漏传时间或不同写入入口产生不一致。

## 注释与可维护性

迁移向每张表及每个业务字段写入 `COMMENT ON TABLE` / `COMMENT ON COLUMN` 中文说明；对所有 `id`、外键、状态、枚举字段、快照字段、JSON 结构和时间字段也分别说明。注释是数据库元数据的一部分，Supabase Table Editor 和数据库客户端可直接读取。

额外优化：

- 为训练计划、训练日、训练动作、训练组、建议和 PR 目标补齐以 `user_id`、计划 ID、训练日状态和日期为主的复合索引，匹配当前页面的主要筛选与排序。
- 为训练结构补齐顺序唯一性约束，防止同一训练日下动作排序重复。
- 保持所有现有检查约束、外键级联语义、匿名访问边界和代理令牌哈希保护不变。

## 验证

1. 增加 SQL 契约测试，断言 11 个前缀物理表、全部兼容视图、注释、时间类型、索引及关键 RLS/RPC 引用存在。
2. 在代码层搜索，确保业务读写不再以旧表名为目标；兼容视图只出现于迁移定义和回归检查。
3. 运行 SQL 契约测试、完整测试、类型检查与构建；以 `release:check` 作为最终本地验证。
4. 执行前遵循数据库发布手册备份。生产 SQL 仅在用户明确要求发布时执行。

## 不在本次范围

- 不修改 `auth.users`、不迁移 Supabase `auth` schema。
- 不改变业务字段的名称、枚举值或训练算法。
- 不将日历日期强制转换成时间戳。
- 不执行生产 Supabase 迁移、部署、推送或删除兼容视图。
