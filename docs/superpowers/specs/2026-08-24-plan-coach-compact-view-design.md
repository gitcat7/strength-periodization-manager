# 计划页 Coach 建议与计划内容紧凑视图设计

## 目标

减少计划页默认全量内容带来的视觉拥挤，同时保留安全、可解释的建议应用流程。页面应让用户先看到当前周期、待处理建议和下一节训练，再按需展开详情。

## 范围

- `Fitness Coach` 待处理建议区增加批量“一键应用”和“一键忽略”。
- Coach 建议区与底部计划内容均支持默认紧凑、手动展开和收起。
- 保留既有逐条建议的重量调整、影响预览、应用和忽略能力。
- 不新增数据库迁移，不修改训练算法、处方规则或现有单条建议 RPC。

## Coach 建议交互

默认状态只显示待处理建议数量、简短说明、`一键应用`、`一键忽略` 与 `展开建议` 控件。展开后显示现有每条建议的动作、建议类型、重量、原因、来源、应用重量输入和逐条操作。

### 批量应用

1. 点击 `一键应用` 收集当前全部 pending 建议及用户已修改的应用重量。
2. 显示合并影响预览：每条建议和受影响的后续训练日。
3. 用户点击确认后，依次复用现有安全应用流程。
4. 处理中禁用重复点击；每次成功后刷新建议和计划数据。
5. 某条失败时停止后续操作，显示中文错误；已成功项保持成功，失败及未处理项仍保留为待处理建议。

批量应用不会绕过影响确认，也不会静默覆盖未来处方。

### 批量忽略

点击 `一键忽略` 先显示待忽略数量确认。确认后逐条复用现有忽略逻辑。成功项刷新移除；若发生失败，显示中文错误并保留失败和未处理项目。取消不写入任何数据。

## 计划内容交互

默认显示计划内容摘要、训练节数和当前/下一节训练卡。其他训练日不在首屏完整展开。点击 `展开完整计划` 后显示完整训练日列表；再次点击可收起。展开后的单个训练日仍遵循已有动作处方、已完成组锁定和本日动作编辑规则。

## 动效与无障碍

- 使用高度和透明度的短过渡，展开箭头随状态旋转。
- `prefers-reduced-motion` 时取消动效。
- 展开控件使用语义化 `button`、`aria-expanded` 与受控区域关联。
- 所有关键操作至少 44px 高，按钮文字使用 `whitespace-nowrap`，不裁切、不缩小至不可读。
- 移动端单列优先；窄屏时整组操作可换行，但单个按钮内不换行。

## 失败处理

网络或 RPC 失败仅展示安全中文提示，不暴露内部异常。批量处理期间禁止重复提交；取消确认、收起区块、展开区块均不写数据库。现有逐条预览/应用/忽略功能保持可用。

## 验收与测试

- Coach 区默认紧凑，展开后展示逐条详情，收起不丢失输入状态。
- 批量应用先预览影响再确认；批量忽略先确认。
- 部分失败保留未处理建议并显示错误。
- 计划内容默认只展示摘要及当前/下一节，展开后完整显示，收起后回到紧凑状态。
- 验证按钮不换行、44px 触控高度、`aria-expanded`、减少动画样式。
- 使用 TDD 先写 RED 测试；完成后运行 focused tests、`pnpm test`、`pnpm release:check` 与 `git diff --check`。
- 固定提交推送后必须通知测试任务独立验收；测试明确“验证通过”前不得部署。
