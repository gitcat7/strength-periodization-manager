# 自定义组间休息与 Coach 专业表达设计

## 目标

在不改变训练处方、Coach 决策、数据库或 RPC 的前提下，让今日训练支持按秒设置组间休息时长，并让今日页和计划页的 Fitness Coach 信息使用一致、专业且可解释的训练语言。

## 范围

### 组间休息

- 仅修改 Today 的组间休息设置与现有浏览器本地持久化值；不新增数据库字段。
- 保留 60、90、120、180 秒快捷档位，新增“自定义秒数”数字输入。
- 输入只接受 30–900 的整数秒。输入为空、非整数或超出范围时显示中文可操作错误，且不覆盖上次有效默认值。
- 在输入失焦或用户确认后保存有效值；刷新页面后继续使用该值。
- 自定义值会用于后续“完成一组后自动休息”和“重置”操作。正在运行的倒计时维持当前剩余秒数，不因修改默认时长跳变。
- 展示保持分钟:秒格式，同时明确当前默认值为“秒”。快捷档位和输入在移动端都不小于 44px 高，不挤压计时控制。

### Fitness Coach 专业表达

- 今日训练的状态卡与计划页待应用建议采用统一的展示语义：
  1. **训练状态或调整方向**：例如“可按计划推进”“建议下调负荷”“建议恢复或延后”“小幅加重”。
  2. **判断依据**：来自既有训练间隔、完成情况、RPE 或原有建议原因；不补造不存在的数据。
  3. **执行建议或影响范围**：以 RPE、RIR（余力次数）、主项/辅助动作和后续训练日说明下一步。
- 今日训练的间隔建议继续由既有 `getInterruptionAdvice` 规则生成，只替换标题和说明的专业措辞，不修改阈值或 load multiplier。
- 计划页继续展示服务端建议的原始 reason，并增加标准化的调整方向/影响范围文案；一键应用、忽略、预览、确认和失败停留行为保持不变。
- 使用中文为主，并首次出现时写作“RIR（余力次数）”；不作医疗、营养或诊断结论。

## 非目标

- 不改变训练计划生成、建议优先级、RPE/完成率阈值、处方重量或进展算法。
- 不增加 SQL migration、schema、RPC、依赖或缓存 key。
- 不改变自由训练、历史、进展、Coach 建议实际保存/应用数据链路。

## 数据与错误处理

- 既有 localStorage 的固定档位设置继续可读取；历史无效值按现有默认 120 秒降级。
- 新自定义值是本地偏好，保存失败时只在当前页面提示，不影响计时与训练记录。
- Coach 所需指标缺失时，保留既有保守结论，不显示虚构的完成率、RPE、恢复或体重判断。

## 验收标准

1. 输入 45、150、300 等有效整数秒后，默认倒计时、重置和刷新后读取均使用该值；快捷档位仍可一键切换。
2. 29、901、小数、负数、非数字和空值不会保存，并有中文提示。
3. 修改默认值不改变正在运行的倒计时剩余时间。
4. Today Coach 卡使用“训练状态 / 判断依据 / 执行建议”结构，且文本与既有间隔规则一致。
5. Plan Coach 建议能看出调整方向、依据和影响范围，原有 reason 与批量应用/忽略流程不回归。
6. 新增 focused 回归覆盖上述逻辑；全量测试和 release check 通过。
7. 遵循项目发布门禁：固定提交推送后先由测试任务明确“验证通过”，再由架构师授权部署，最后进行正式域名 14 路由与 `/api/health` 冒烟。
