# 存量用户画像数据入口设计

## 目标

让已有周期计划的用户无需重建计划，即可补充或更新体重、饮食与恢复数据。

## 方案

在计划页的现有周期操作区增加“更新体重、饮食与恢复”按钮。点击后展开独立轻量表单，复用现有画像字段：当前体重、目标体重、近 14 天体重变化、饮食执行度、蛋白质目标达成和恢复状态。

保存操作仅 `update` 当前用户的 `usr_athlete_profiles` 画像字段；不会调用计划重建 RPC，不修改 `plan_programs`、`plan_workouts`、训练记录或主项工作组。目标体重按当前所选周期换算为已存在的每周体重变化字段，供下次计划重建读取。

## 交互与错误处理

- 有现有计划时显示入口；首次建计划继续使用完整计划表单。
- 保存成功后收起表单并显示“已保存；下次重建计划会使用这些数据”。
- 校验沿用 `validatePlanSetup` 的体重范围与目标/当前体重依赖关系。
- 保存失败保留用户输入并展示数据库返回的错误信息。

## 验证

- 组件测试确认有计划状态显示独立入口，表单包含体重输入与保存按钮。
- 域测试确认 70 kg 到 65 kg、12 周换算为 -0.42 kg/周。
- 完整发布检查、生产部署和线上冒烟检查。
