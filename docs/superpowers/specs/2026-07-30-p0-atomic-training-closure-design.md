# P0 原子训练闭环设计

## 审计结论

“需求”窗口提出的四项 P0 中：

1. 未达成计划却建议加重：已修复。Coach 已同时判断完成组、目标重量、目标次数和 RPE。
2. 接受建议抹平 A/B 与减量差异：已修复。后续重量按原处方比例缩放并按器械增量取整。
3. 用户画像不影响计划：已修复。目标、经验、训练最大重量、恢复、饮食、体重变化、时长和结构化动作限制已进入处方。
4. 完成训练缺少统一原子规则：部分修复，仍是 P0。

第 4 项当前剩余问题：

- Web 先完成训练，再单独插入 Coach 建议；建议写入失败时，训练已经完成。
- Agent 虽复用完成 RPC，但不会生成 Coach 建议。
- 历史训练修改后，原有待处理建议仍可继续应用。
- Agent 记录已完成组仍允许 `0kg` 或 `0次` 进入组日志。
- Agent 记录第一组时没有启动实际训练时长。

## 方案选择

### 采用：数据库事务作为唯一完成入口

把组记录终态校验、训练完成、实际时长确认和 Coach 建议写入收口到同一个 Supabase RPC。PostgreSQL 函数天然处于同一事务，任一步失败都会整体回滚。Web 与 Agent 只调用同一个入口。

### 不采用：继续由前端串联写入

即使增加补偿重试，页面关闭、网络中断或重复点击仍可能留下半完成状态；Agent 也会继续与 Web 行为不一致。

### 不采用：暂时关闭 Coach 建议

可以规避半完成，但会破坏核心产品闭环，也不能解决历史修改后的建议失效和 Agent 组数据问题。

用户已预先授权采用推荐方案，因此无需再次确认。

## 原子完成 RPC

保留现有 `complete_training_workout` 名称以及训练时长参数兼容，在内部增加建议生成。

一次调用必须完成：

1. 根据认证用户或受控的 service-role `p_user_id` 校验训练归属。
2. 对训练行加锁。
3. 校验所有计划组均存在、已完成，且实际次数、实际重量和 RPE 满足动作类型要求。
4. 校验或计算 `duration_seconds`。
5. 删除该训练尚未处理的旧建议，避免重复提交产生重复项。
6. 根据数据库中的最终组记录生成新的 pending Coach 建议。
7. 写入建议。
8. 写入 `status = completed`、`completed_at` 和最终时长。
9. 返回训练状态、时长和建议列表。

任何一步报错时，训练状态和建议都不得部分提交。

重复调用已完成训练时保持幂等：不覆盖首次完成时间和最终时长，不重复创建建议，返回现有结果。

## 服务端 Coach 规则

数据库建议规则必须与当前 TypeScript 规则保持一致，并覆盖主项的安全门：

- 完成不足一半：减量约 10%。
- 有未完成组或任一完成组未达到目标重量/次数：主项小幅降重。
- RPE 缺失：保持。
- 平均 RPE ≥ 9：主项小幅降重。
- 全部达标且平均 RPE ≤ 7：主项按器械增量加重。
- 其余：保持。
- 非主项不得因为低 RPE 自动加重；默认保持或按现有保守规则处理。
- 所有重量按 `default_increment` 取整。

规则集中在数据库内部函数中，完成 RPC 和历史修订 RPC 共用，避免复制两套 SQL。

## 历史修订 RPC

新增 `revise_completed_workout_logs(p_workout_id uuid, p_logs jsonb)`：

1. 校验训练归属且训练已经完成。
2. 校验提交的组只属于该训练，不允许跨训练更新。
3. 原子更新实际重量、次数、RPE和完成状态。
4. 将该训练当前 `pending` 建议标记为 `rejected`。
5. 根据修订后的最终组记录生成新的 pending 建议。
6. 返回更新后的组记录和建议。

已经 `accepted` 或 `modified` 的建议不自动回滚未来计划，避免无提示地修改用户已经确认的计划；历史页明确提示“已重新生成待处理建议，已应用的历史调整不会自动撤销”。

## 完成组数据约束

数据库增加 completed set 校验触发器或等价约束：

- `completed = true` 时 `actual_reps > 0`。
- 需要 RPE 的力量动作必须有 `1–10` RPE。
- 负重动作必须有正数重量。
- 自重动作允许重量为空或 0。
- 辅助重量允许 0，但不允许负数。
- 现有有氧免 RPE 规则保持。

Agent API 同步收紧：

- `completed` 默认为 true 时，次数必须大于 0。
- 负重训练实际重量必须大于 0。
- 写第一组之前先调用幂等 `start_training_workout`，保证训练时长可完成。
- Agent 完成训练继续调用统一完成 RPC，并获得相同 Coach 建议。

## Web 调整

今日训练页：

- 保留组日志保存。
- 完成时只调用统一完成 RPC。
- 删除完成后的客户端建议插入。
- 使用 RPC 返回的建议更新成功摘要。
- RPC 失败时训练保持未完成，用户输入不丢失。

历史页：

- 保存历史修改时调用历史修订 RPC，不再直接批量 upsert。
- 刷新本地组记录、建议和相关缓存。
- 展示重新生成建议的明确提示。

## 验收标准

- 模拟建议插入失败时，训练完成事务整体回滚。
- Web 与 Agent 完成同一份数据时产生相同建议。
- 重复完成不会重复建议。
- 不达标组绝不生成加重。
- 历史修订后旧 pending 建议不可再应用，新建议基于修订数据。
- Agent 不能记录 `0次` 的已完成组，负重动作不能记录 `0kg`。
- Agent 首组记录启动训练时长。
- TypeScript 建议规则与 SQL 规则具有共享契约用例。
- 全量测试、类型检查、生产构建、本地冒烟和线上冒烟通过。
