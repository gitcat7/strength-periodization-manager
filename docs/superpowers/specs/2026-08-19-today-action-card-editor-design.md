# 今日计划动作卡编辑设计

## 背景

计划页当前通过一块独立的“编辑本日动作”表单修改训练日处方。每个动作长期显示为下拉框，并把更换、调序、删除和参数输入压在同一行；在电脑端仍显拥挤，动作名称还可能呈现为空白选择框。新增入口只出现在整块表单底部，用户无法直观看出新动作会插入哪里。

本次只优化未完成计划日的动作结构编辑体验，不修改训练生成、实际训练记录、分析算法或数据库权限。

## 目标

- 当训练日可编辑时，每一个现有动作都能直观地新增后续动作或删除自身。
- 动作名称始终以可读文本展示，不再用常驻下拉框充当标题。
- 保留更换、调序以及目标组数、次数、重量编辑能力。
- 保留现有单事务保存、版本锁和完成组安全边界。
- 电脑与移动端均保持清晰的层级和至少 44px 的触控目标。

## 非目标

- 不允许编辑已完成、已跳过、休息或归档训练日。
- 不允许在已有任意完成组后继续新增、删除、更换或调序动作。
- 不接受外部动作或自由文本动作；仅使用同方向的本地审核动作。
- 不修改 Today 的组记录交互、History、Progress、e1RM、Coach、CSV 或计划生成算法。
- 不新增数据库迁移，不修改 `revise_workout_prescription` RPC。

## 交互设计

### 默认状态

计划页训练日继续只读展示动作名称和处方。只有本人当前活动计划中状态为 `scheduled` 或 `draft`、类型为训练日且完成组数为 0 的训练日显示“编辑本日动作”。

### 编辑状态

点击入口后，所有动作以独立卡片呈现。每张卡包含：

- 固定显示的动作名称和当前序号；
- 目标组数、次数、重量输入；
- “更换动作”“上移”“下移”“删除动作”按钮；
- 卡片下方的“在此动作后新增”按钮。

“更换动作”和“在此动作后新增”按需展开动作选择器，选择器只列出当天方向兼容、尚未使用的本地审核动作。更换后保留当前动作的组数、次数和重量；新增动作默认使用 2 组、8 次、0kg，并立即插入所点击卡片之后，用户可继续修改处方参数。

删除只修改本地草稿。至少保留一个动作；只剩一个动作时禁用删除并说明原因。删除后在编辑区域显示可撤销提示，撤销会把动作和原有处方恢复到原位置。最多允许 12 个动作；达到上限时隐藏或禁用新增入口并说明原因。

取消编辑会丢弃本次草稿，不写数据库。保存仍分为“预览并保存”和“确认保存”两步，摘要显示新增、删除和顺序变化。

## 数据流与安全

编辑器继续在浏览器内维护完整 `WorkoutPrescriptionDraft`。新增、删除、更换、调序和参数修改均只更新草稿。确认保存时：

1. 通过 `validateWorkoutPrescriptionDraft` 校验动作数量、连续顺序、重复动作、方向和数值范围；
2. 通过 `buildWorkoutPrescriptionPayload` 生成完整动作列表；
3. 只调用一次 `revise_workout_prescription(workout_id, expected_revision, payload)`；
4. RPC 在单事务内再次验证用户、活动计划、训练日状态、完成组、动作来源、方向和 revision；
5. 成功后清理相关计划与训练草稿缓存并重新读取当前计划。

浏览器不得通过多次表写入拼接新增或删除。网络失败、字段校验失败或 revision 冲突时保留当前草稿；错误信息使用安全中文，不暴露数据库字段或内部异常。成功后才关闭编辑状态。

## 组件边界

- `WorkoutPrescriptionEditor`：管理打开状态、草稿、撤销记录、保存预览和 RPC 结果。
- 动作卡子组件：展示动作名称、参数输入和单个动作的更换、调序、删除、新增入口。
- 现有领域函数：继续负责草稿验证、payload 和变更摘要；如需插入/删除/撤销纯函数，应放入现有 `workout-prescription-editor` 领域模块并单测。
- `ProgramManager`：继续提供训练日、动作目录和保存后重新加载，不承担草稿变换逻辑。

本次只做与动作卡布局和草稿操作直接相关的拆分，不重构计划页其他区域。

## 错误与边界状态

- 已有完成组：不渲染编辑入口；服务器继续拒绝绕过前端的请求。
- 最后一个动作：删除按钮禁用并提供可读说明。
- 12 个动作：新增按钮禁用并提供可读说明。
- 无同方向可用动作：新增/更换选择器显示“暂无可用动作”，不提交空值。
- revision 冲突：提示刷新后重试并保留草稿，避免静默覆盖。
- 保存失败：编辑器保持打开，按钮恢复可操作，允许重试或取消。
- 保存成功：关闭编辑器、清空撤销状态、刷新计划，Today 使用新处方。

## 测试与发布门禁

按 TDD 先补失败测试，再做最小实现。至少覆盖：

- 所有动作卡均显示删除和“在此动作后新增”入口；
- 动作名称以文本显示，默认 DOM 不存在常驻的动作替换下拉框；
- 新动作插入到所点击动作之后，并生成连续顺序；
- 更换动作、上移、下移和处方参数编辑不回归；
- 删除任意动作后可撤销，最后一个动作不可删除；
- 最多 12 个动作且不得重复、跨方向或使用外部动作；
- 已有完成组、非活动状态和休息日不显示编辑器；
- 取消零数据库调用，保存失败保留草稿；
- 保存成功只调用一次 RPC，使用最新 revision，并重新加载计划；
- 375/390/430px 与电脑宽度下无横向溢出，操作按钮至少 44px；
- Today、History、Progress、e1RM、Coach 与 CSV 的既有回归测试继续通过。

完整门禁为 focused 测试、`pnpm test`、`pnpm release:check` 和 `git diff --check`。提交推送后交给独立测试窗口；测试明确“验证通过”前不部署。部署后运行正式域名 14 路由与 `/api/health` 冒烟，并进行真实登录态计划页交互核验。

## 数据库与发布影响

本次不包含 SQL migration、schema 或 RPC 修改，不需要用户执行 SQL。发布只包含前端与测试改动。
